# Проект бизнес-логики и API для MVP Farposton

Всё ниже, кроме раздела «Факты», — предложение. Имена файлов, полей и пороги с репозиторием не сверялись, как вы и просили.

## Факты (из задачи)
- Всего 4567 точек: у 89 есть `congestion` от 2ГИС, у 4478 — искусственный индекс 0–100 по часам недели. В сумме это ровно 4567, то есть у каждой точки один источник.
- У `congestion` шкала, дата и происхождение не расшифрованы.
- Шкалы несопоставимы, и ни одна не означает число посетителей или свободные столы.
- Онлайн-данных нет, квота исчерпана — во время работы MVP к 2ГИС не обращается.
- Данные лежат раздельно в JSONL, у каждой записи есть метка происхождения.

## Источники и статусы карточки
| Статус `load.source` | Откуда | Что показываем |
|---|---|---|
| `synthetic` | синтетический JSONL | условный уровень по часам с пометкой «демо» |
| `provider_unverified` | снимок 2ГИС | сырое значение без нормализации и цвета |
| `none` | запись отсутствует или не прошла проверку | «нет данных» |

- **Расписание:** `schedule.source` принимает `known` или `assumed`. Допущение — ежедневно 10:00–22:00, оно всегда приходит с флагом.
- **Показ 89 значений 2ГИС:** держать за флагом, по умолчанию выключенным. AGENTS.md запрещает сохранять ответы 2ГИС до подтверждения условий, так что это ваше решение. При выключенном флаге карточка получает `none`.

## Модели (stdlib, без новых зависимостей)
```python
@dataclass(frozen=True)
class Interval:            # принадлежит дню открытия
    day: int               # 0=пн
    open_min: int          # минуты от 00:00
    close_min: int         # >1440 — закрытие после полуночи

@dataclass(frozen=True)
class Schedule:
    source: Literal["known", "assumed"]
    intervals: tuple[Interval, ...]

@dataclass(frozen=True)
class Load:
    source: Literal["synthetic", "provider_unverified", "none"]
    hourly: tuple[int, ...] | None   # 168 значений, только synthetic
    raw: str | None                  # только 2ГИС, как в записи
# продолжение: Load закрыт тремя полями выше
@dataclass(frozen=True)
class Venue:
    id: str
    name: str
    address: str | None
    lat: float
    lon: float
    schedule: Schedule
    load: Load
    origin: str  # метка происхождения записи из JSONL
```

## API

- `GET /api/venues?q=&day=sat|sun&hour=0..23&open_only=0|1&level=low|medium|high&sort=name|load&limit=&offset=`
- `GET /api/venues/{id}?day=&hour=`

Без `day` и `hour` берётся текущий час в `Asia/Vladivostok`. Названия и значения в примерах условные.

```json
{
  "at": {"day": "sat", "hour": 20, "tz": "Asia/Vladivostok"},
  "total": 4567,
  "excluded_unknown": 0,
  "items": [
    {"id": "v1", "name": "Кафе А", "open": true, "schedule_source": "known",
     "load": {"source": "synthetic", "demo": true, "level": "high", "index": 78}},
    {"id": "v2", "name": "Бар Б", "open": true, "schedule_source": "assumed",
     "load": {"source": "none", "demo": false, "level": null, "index": null}}
  ]
}
```

Карточка в `detail` дополняет элемент списка:

```json
{
  "id": "v1",
  "schedule": {"source": "known", "intervals": [
    {"day": "sat", "open": "18:00", "close": "02:00", "closes_next_day": true}]},
  "load": {"source": "synthetic", "demo": true, "level": "high", "index": 78,
           "day_hours": "24 значения, null для закрытых часов"}
}
```

- **Уровень:** пороги 0–33 `low`, 34–66 `medium`, 67–100 `high` применяются только к `synthetic`.
- **Закрытый час:** `level` и `index` равны `null` при любом значении индекса.
- **2ГИС:** поле `load.raw` появляется только при включённом флаге и только у `provider_unverified`, без уровня и цвета.

## Фильтрация и сортировка

- **`open_only=1`:** оставляет открытые по известному или допущенному графику; допущенные идут с `schedule_source: "assumed"`.
- **`level=`:** отбирает только `synthetic`. Число отброшенных карточек без уровня возвращается в `excluded_unknown`.
- **`sort=load`:** сначала открытые `synthetic` по возрастанию индекса, затем закрытые, затем `provider_unverified` и `none`. При равенстве порядок по имени и `id`.
- **Неизвестное:** не приравнивается к 0, значение 2ГИС в сортировке не участвует.

## Расчёт дня и часа

- **Время:** `datetime.now(ZoneInfo("Asia/Vladivostok"))`. Перехода на летнее время нет, поэтому в неделе всегда 168 часов.
- **Открыто:** для дня `d` и часа `h` берём `m = h*60`. Час открыт, если он пересекает интервал дня `d` (`open_min < m+60` и `m < close_min`) или интервал дня `(d−1) mod 7` (`open_min < m+1500` и `m+1440 < close_min`).
- **После полуночи:** суббота 01:00 считается по пятничному интервалу, понедельник 01:00 по воскресному.
- **Индекс:** `hourly[d*24 + h]`, где `d=0` это понедельник. Это гипотеза: начало синтетической недели нужно сверить с файлом.
- **Нет графика:** подставляется 10:00–22:00 с `source: "assumed"`.

## Формулировки UI

- «Условная загруженность: высокая» с меткой «демо-данные, не измерение».
- «Нет данных о загруженности».
- «График работы — допущение, уточняйте у заведения».
- «Значение 2ГИС, шкала не расшифрована».
- Слов «свободно», «столы», «посетителей», «прогноз» в интерфейсе нет.

## Ограничения

- Синтетический индекс ничего не говорит о реальном заведении; точность не оценивается.
- Шкалы 2ГИС и синтетики не сводятся в одну.
- Модель Forecast не используется.
- Онлайн-запросов к 2ГИС нет.

## Проверки

1. Интервал сб
18:00–02:00: вс 01:00 открыто, вс 02:00 закрыто.
2. Пн 01:00 считается по интервалу воскресенья (`(d−1) mod 7`).
3. Нет расписания: 10:00–22:00 и `schedule.source = assumed`, флаг виден в списке и карточке.
4. 89 + 4478 = 4567, у каждой записи есть метка происхождения.
5. `sort=load` и `level=` не смешивают значение 2ГИС с синтетикой; `excluded_unknown` равен числу отброшенных карточек.
6. Флаг выключен: у 89 карточек `load.source = none`, поля `raw` нет.
7. Закрытый час: `level` и `index` равны `null`, а не 0.
8. Без `day` и `hour` берётся текущий час `Asia/Vladivostok`, а не время сервера.
9. В UI нет слов «свободные столы» и «посетителей»; у синтетики стоит метка «демо».
