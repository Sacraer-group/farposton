## Компоненты

1. **Хранилище** — `web/places/store.py`. При старте читает два JSONL из каталога, заданного переменной окружения (локально `.demo/places/`), проверяет строки и держит два отдельных набора в памяти. База на 4567 записей не нужна.
2. **API** — `web/places/api.py`, один `APIRouter`, подключается одной строкой в `web/app.py`.
3. **Страница** — маршрут `/places`, файлы `web/static/places.html` и `web/static/assets/places.js`. `index.html` и `app.js` не трогаем.
4. **Карта** — отдельный шаг, зависит от решения по подложке. Без решения остаётся список с координатами.
5. **Флаг `PLACES_ENABLE_2GIS`**, по умолчанию выключен. Пока права не подтверждены, MVP работает только на 4478 синтетических точках.

## API

- `GET /api/places?q=&source=&day=&hour=&limit=&offset=` — поиск по названию и адресу, список.
- `GET /api/places/{id}?day=&hour=` — карточка.
- `GET /api/places/meta` — число записей по источникам, число отброшенных строк, тексты маркировки.

## Контракт записи

```
id        строка с префиксом источника: "syn:…" / "2gis:…"
name, address, category   строка | null
lat, lon  число | null
load:
  source  "synthetic_index" | "2gis_congestion"   (обязательно)
  value   число | null      (сырое, без пересчёта)
  day, hour                 запрошенный срез | null
  status  "ok" | "no_data" | "no_hourly" | "unknown_semantics"
  label   текст маркировки для интерфейса
```

## Поток данных

```
JSONL синтетика ─┐                      ┌─ набор syn ──┐
                 ├─ store: проверка ────┤              ├─ API ─ /places
JSONL 2ГИС ──────┘  (флаг, права)       └─ набор 2gis ─┘   список · карта · карточка
                                                           всегда source + label
```

## Как исключить смешивание

- Наборы не объединяются. У каждой записи ровно один источник.
- Значения не нормализуются в общую шкалу. Общего цвета, рейтинга и среднего нет.
- Сортировка и фильтр по `load` требуют параметра `source`, иначе ответ 400.
- На карте у источников разные маркеры и легенда. Цветовая шкала есть только у синтетики и подписана «условный индекс».
- Если заведение окажется в обоих файлах, показываем две записи и не выбираем «лучшую».
- Для 2ГИС выводим сырое значение с подписью «congestion 2ГИС, смысл шкалы не подтверждён». Если среза по часам нет, выбор дня и часа к нему не применяется, статус `no_hourly`.

## Пропуски

- Нет координат: запись есть в списке, на карте её нет.
- Нет значения на выбранный час: `value: null`, `no_data`. Никакой интерполяции, нуля или соседнего часа.
- Битая строка JSONL: пропускается, счётчик виден в `meta`.
- Файл отсутствует или флаг выключен: источник помечен в `meta` как недоступный, страница работает на втором.

## Критерии проверки

1. `meta` возвращает 4478 и 89 (при включённом флаге), либо расхождение объяснено счётчиком отброшенных строк.
2. Тест: ни один ответ не содержит `value` без `source` и `label`.
3. Тест: сортировка по загрузке без `source` даёт 400.
4. Тест: час без данных даёт `null` и `no_data`.
5. `/`, `/accuracy`, `/weekly-demo`, `/analytics` работают как прежде, `make test` проходит.
6. Маркировка источ
**6. Маркировка источника** видна в списке, на карте и в карточке у каждого показанного значения. Значения без подписи на экране нет. Слов «прогноз» и «свободно» нет ни в интерфейсе, ни в ответах API.

## Порядок этапов

**День 1**
1. `web/places/store.py`: загрузка двух JSONL в два отдельных набора, валидация, счётчик отброшенных строк. Нужны реальные поля файлов или хотя бы 5–10 строк из каждого.
2. `web/places/api.py` и тесты на контракт: 400 при сортировке без `source`, `null` при пропуске. Зависит от шага 1.
3. Страница `/places`: поиск, список, карточка. Зависит от шага 2.

**День 2**
4. Выбор дня и часа, подписи источника, легенда. Зависит от шага 3.
5. Карта. Зависит от решения по подложке; без него в списке остаются координаты.
6. Включение `PLACES_ENABLE_2GIS`. Зависит от подтверждённых прав и от понимания смысла `congestion`; иначе флаг остаётся выключенным, и MVP сдаётся на синтетике.
7. Регресс старых маршрутов (`/`, `/accuracy`, `/weekly-demo`, `/analytics`) и `make test`.

Шаги 5 и 6 можно отложить, не ломая остальное.

## Риски

- **Права 2ГИС.** Хранение и показ 89 записей могут оказаться недопустимыми; тогда их нужно удалить, а не только скрыть.
- **Смысл `congestion`.** Неизвестны единицы, момент измерения и наличие почасового разреза. Возможно, это одно число без времени; тогда статус всегда `no_hourly`.
- **Ложное прочтение.** Пользователь примет условный индекс за реальную загрузку. Подпись снижает этот риск, но не устраняет.
- **Пересечение наборов.** Сумма 89 + 4478 = 4567 — гипотеза; дубли между файлами не проверялись.
- **Качество JSONL.** Возможны пустые координаты, битые строки и разные схемы в двух файлах.
- **Подложка карты.** У неё своя лицензия и, возможно, свой ключ.
