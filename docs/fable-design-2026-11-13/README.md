# Проектирование Farposton: поручения Fable

13 ноября 2026 г. Fable подготовил черновики для продукта поиска заведений Владивостока:

- `interface-fable-draft.md` — пользовательские сценарии, экраны и состояния;
- `data-logic-fable-draft.md` — модель данных, API и обработка данных;
- `architecture-fable-draft.md` — компоненты и порядок создания MVP;
- `decisions-fable.md` — уточнённые предложения после проверки черновиков.

Черновики содержат ответы Fable; в одном исправлена разметка блока кода. Они не означают, что интерфейс реализован, архитектура принята или названные файлы существуют. Попытки Fable самостоятельно исследовать весь контекст для задач логики и архитектуры закончились ошибкой compaction; эти два документа получены в повторных запросах по переданной сводке без чтения исходников. Для интерфейса агент прочитал части существующих исходников, но часть выдачи была усечена.

## Проверенные уточнения перед реализацией

1. Собранные данные охватывают 4 567 уникальных точек: 89 с исходным полем `congestion` 2ГИС и 4 478 с искусственным недельным индексом. Наборы проверены на отсутствие общих ID. Это неполная поисковая выборка по городу.
2. Семантика уровней 2ГИС не подтверждена. Нельзя на её основе называть часы «спокойнее» или «оживлённее», сравнивать заведения между собой, сортировать по загруженности или заявлять наличие столиков. Демо-индекс тоже не отражает реальную посещаемость и не сопоставлен с профилем 2ГИС.
3. В файле логики Fable ошибочно указал резервное расписание 10:00–22:00. Фактический генератор использовал 09:00–21:00 ежедневно при отсутствии расписания — только как допущение генерации, а не установленный график работы.
4. Условия хранения и показа требуют выяснения для всех карточек 2ГИС, включая те, к которым добавлен искусственный профиль; выключение только профиля `congestion` само по себе этот вопрос не решает.
5. Первый ключ Places API заблокирован по исчерпании лимита. Второй работал при сборе; его текущий остаток не проверен. Точный контракт JSONL и права на карту надо проверить перед выбором интеграции.
6. Fable предложил отложить карту и оставить старое приложение без изменений. Это не утверждённое решение пользователя; в частности, подключение новых маршрутов к существующему приложению может потребовать изменения `web/app.py`.
7. Старые товарные модели Forecast не обучены для прогноза посещаемости. Текущие сгенерированные значения — однотипный демонстрационный недельный шаблон, не история посещений и не подтверждённый прогноз.

Проектные документы не развернуты и не подключены к действующему сервису.
